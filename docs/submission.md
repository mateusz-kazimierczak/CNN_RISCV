# Submission guide

## Midterm entry points

Use [the README's midterm index](../README.md#midterm-submission) for the
ISA/Spike submission. The [presentation](https://docs.google.com/presentation/d/1C1yH6lDG07P288sPAHhANP2DuaQ6jViiKXMT8TjxvKU/edit?usp=sharing)
has anyone-with-the-link reader permission (checked 2026-10-27).
Code, model, configuration, verification, profiling and operator/microbenchmark
results are linked there. The [written report source](../reports/midterm/main.tex)
remains a placeholder scaffold and must not be described as a completed report.
The assignment distinguishes the midterm ISA/Spike milestone from the final
CV-Wally/hardware-cost evaluation; the broader deliverables below remain useful
for that later milestone.

## Full-project deliverables

The assignment is [instructions.md](../instructions.md), with
[clarifications.md](../clarifications.md). The repository entry points are
[DESIGN.md](../DESIGN.md), [EXPERIMENTS.md](../EXPERIMENTS.md) and
[AI_USAGE.md](../AI_USAGE.md). Existing source directories are retained so
recorded build paths and historical evidence stay usable.

The [unified evidence package](../results/submission/README.md) is the main
submission entry point. It joins the cumulative software sequence to the grouped
hardware-era progression, with explicit substages, controls and archived RTL
cycle evidence. Run `gmake submission-report` to regenerate and cross-check it.
Run `gmake submission-package` to create the local source/evidence tarball,
file manifest and checksum under `build/submission/`. The archive retains the
selected immutable Spike captures and RTL snapshots so the hardware/unified
reports can be checked without retrieving those evidence files from another host.
Pinned dependency/toolchain setup is still required, and native diagnostic
builds are regenerated by the software workflow.

Full-model RTL simulation has already passed for A0 (stored as B0), accepted B1 and X1–X5;
[the preserved table](../results/cvw/full-x5/README.md) records simulated cycles
and retirements. Those runs are separate from the new intermediate software
stages. Area and physical timing remain unavailable because the baseline
Design Compiler smoke failed at startup with `DCSH-1`; see
[the synthesis status](../results/synthesis/baseline/README.md). Resolving that
external CAD entitlement/startup problem is still required for hardware-cost
and speedup/area claims.

Synthesis source/configuration/test files are part of the submission. Only
`synth/results/` raw jobs and `synth/configs/*.local.json` machine-specific access
settings are ignored; the full synthesis directory must not be excluded.

Before packaging, regenerate the cumulative sequence and report, retain the
compact tracked summaries and CSV/SVG artifacts, and include any raw evidence
required by the submission venue separately from Git. See
[experiments/README.md](../experiments/README.md) for the clean-checkout workflow.

The software chart has seven presentation bars: A0 (LiteRT baseline), B1.1 (custom compiler), B1.2, B1.3,
B1.5 (including separately measured B1.4), B1.6 and B1.7. Use the reordered
presentation deltas, not the historical OC4 deltas. Report byte-exact output,
repeat agreement, code/constants footprint and operator costs alongside counts.

Continue with accepted X1, X2, X3, X4 and X5. Main X1 means the final 2×4 packed
configuration and main X2 means the final outlined/wide-ADD configuration.
Retain X1.1–X1.4 and X2.1–X2.3 as supporting measurements, X3.broad as a sibling
trial from optimized X2, and D1 as a software-only ablation before X4. X5 reuses
the exact X4 hardware. Full-model RTL cycles are available for accepted main
stages; D1 and compiler substages remain without cycle measurements.

Hardware cycle/CPI, area/Fmax and speedup-per-area claims must cite a compatible
RTL/synthesis configuration and completed evidence. Existing RTL guides and
result directories document their own coverage and limits. Software instruction
ratios alone cannot complete those hardware requirements. This guide makes the
remaining final deliverables visible; it does not certify a completed final
report or presentation.
